# Medium-sized PDF benchmark (opener-1074)

Run `PYTHONPATH=. python3 medium_pdf_benchmark.py --runs 5` after installing
`requirements-enhanced-pdf.txt`. The harness builds a **deterministic ~4 MiB,
128-page PDF 1.7** entirely in memory. The pages share one inert content stream
containing whitespace; this is deliberately a structure-analysis workload, not
a representative rendering, download, antivirus, or interactive-document workload.
The generated bytes contain no scripts, embedded attachments, external links,
or user documents.

Each run exercises the **real, supervised `parse_pdf_structure_timed` worker**
with its existing process boundary and deadline. One unreported warmup precedes
1–10 timed samples. JSON reports input bytes, page count, median and nearest-rank
95th-percentile wall-clock milliseconds. Samples must return a valid, non-authorizing
structure record; failures fail the benchmark rather than being counted as fast
samples. The timings are **not end-to-end PDF opening times** and must not be
presented as user-facing performance guarantees or compared across machines
without controlling for CPU, OS, Python version, runner contention and warmup.

CI runs contract/corpus tests and a three-sample smoke measurement. CI asserts
**correct behavior, not a fixed latency threshold**, because hosted-runner timing
is variable. Results are observed in job logs, not checked into the repository.
This benchmark does not invoke `clamscan`, inspect local user files, clear
quarantine, update preferences, enable optional protection, or authorize PDF
opening; the installed Built-in scanner remains the only active admission gate.
