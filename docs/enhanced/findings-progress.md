# Enhanced findings in the native scan progress panel — opener-0303

The native \`ScanProgressPanel\` can now display the existing explainable Enhanced analysis **schema v2** from [opener-0299](finding-explanations.md), including known inspection stages, finding codes, severities and handling results. Call \`panel.updateEnhancedFindings(from: reportData)\` with the UTF-8 JSON bytes of a trusted \`explain_analysis_findings(report).to_dict()\` result. Supply \`nil\` to clear the previous document's report, hide the section, and restore the original panel size.

Only a controlled vocabulary of known stages and findings is rendered. PDF-supplied scripts, filenames, URL values, exception messages and producer-supplied explanation text are never interpolated. Inconsistent, unsupported or oversized JSON shows **Enhanced findings unavailable** and a non-approval notice; it never shows a clean fallback. Incomplete and unrun stages remain visible. Even a zero-finding report expressly says it is **not a clean verdict**. The panel offers a bounded, scrollable, read-only list with accessibility identifiers and labels; reports with more than 64 result rows explicitly disclose the number omitted, rather than implying an exhaustive on-screen list.

The currently deployed Built-in ClamAV gate supplies no Enhanced findings because **Enhanced is not enabled**. This is a presentation surface for a future trusted analysis producer, not a new scanner, producer, file-opening verdict, preference toggle or PDF content executor. The UI method never changes the built-in scan process, clean-cache, signature freshness, quarantine, verified handoff, browser selection or cancel behavior. Future Enhanced integration must enforce all mandatory inspections and per-document report ownership independently before sending snapshots to the view.

The existing required macOS \`test-scan-progress-component.py\` integration harness now compiles the same production \`scan-progress-view.swift\` and exercises valid, missing-stage, invalid, oversized, empty and cleared findings; it also verifies scanner/profile, progress indicator, Cancel and existing layout behavior. The existing \`macos-build\` job runs this harness without altering shared CI wiring.
