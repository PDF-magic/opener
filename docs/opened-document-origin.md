# Record opened PDF origin (opener-0326)

The deployed scanner now records whether **the document that successfully
opened** was the original file or a generated sanitized copy. Unlike scan
requests and intended destinations, opening origin is written only after
`launch_clean_file` succeeds; blocked scans, failed launch attempts, and failed
fallbacks produce no opened-document record. A successful alternate-browser
handoff creates one record, never one per launch attempt.

A new `opened_document_origins` table in the existing private
`scan-requests.sqlite3` database records `opened_at` and the fixed
`document_origin` enum (`original` or `generated-copy`). **No document
path, filename, PDF content, URL, scan verdict, or source identifier is
stored.** The audit routine rejects unsafe database files and symlinks,
requires private single-link regular files, and uses SQLite transactions.

Classification is owned by the scanner: normal `scan_and_open` records
`original` even if a caller supplies misleading request metadata. The
previously merged `scan_and_open_generated_copy` entry point records
`generated-copy` after validating exact output bytes, requiring a fresh
ClamAV scan, and performing the unchanged launch-integrity checks. This
metadata **never authorizes opening**, and an audit-storage failure cannot
relabel a failed malware scan or report an already-opened document as
blocked. Existing clean-cache behavior, settings, signature updates and
quarantine remain unchanged.

Coordination: the separately developed Maximum safe-copy routing in
[PR #215](https://github.com/PDF-magic/opener/pull/215) currently invokes the
ordinary `scan_and_open` entry point for its staged copy. Before making
that pending route selectable, its caller must switch to the validated
generated-copy scan entry point (or an equivalent trusted generated-copy
origin integration); **a filename or staging directory cannot establish
provenance**. This change does not rewrite #215 or activate Maximum.

Dedicated Linux and macOS CI exercises successful original and generated
handoffs, cached originals, rejected malware/incomplete scans, failed and
successful fallback launching, mismatched generated bytes, private audit
storage, and audit-storage failure compatibility.
