# Native messaging webpage ingress boundary (opener-0661)

The shared browser extension remains intentionally inactive. It has no content scripts, externally connectable messages, native messaging permission, page event bridges, or active native host connections. Website code cannot use the native host directly through this extension. The existing source and packaged Chromium/Firefox manifests and background scripts retain these restrictions.

The pure `native-page-ingress.js` module provides an additional **fail-closed boundary for a future trusted, internal extension messaging adapter**. Create it using the browser-controlled `runtime.id` and `runtime.getURL("/")`, plus a separately trusted read-only callback. Bind `handleRuntimeMessage` **only** to the browser's own internal `runtime.onMessage` listener, passing the browser-delivered `sender` untouched. Never use the external-message listener, DOM events, `window.postMessage`, page-supplied sender objects, or content-script relays as authorization.

The gate requires an exact matching extension ID and internal extension URL, rejects any sender with a `tab` or `frameId`, denies webpage/file/other-extension origins, and fails closed for absent or malformed context and hostile objects. Only bounded, version-one, null-payload `host.ping` and `host.health` requests reach the callback as detached immutable records. All scan, cancellation, opening, executable, host-handshake, permission-change, arbitrary payload, and user-asserted authorization requests are rejected. It neither registers listeners nor sends native messages itself.

This is defense-in-depth, **not browser process authentication**, user consent, a scanner readiness signal, or proof that a caller is entitled to privileged operations. The future adapter must independently validate registered host identity, browser permissions, explicit user action, and actual source provenance. Keep the scanner's ClamAV freshness, complete scan, integrity, quarantine and user-selected PDF application guarantees authoritative. No current app behavior or preferences change.

Seven regression tests run as part of the existing WebExtensions `npm test` suite in required CI, including both built worker/manifest variants. They exercise forged webpage senders, external origins, content-script frames, malformed requests, unsafe getters and the read-only boundary.
